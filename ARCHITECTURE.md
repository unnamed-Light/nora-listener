# Техническая архитектура и реализация Nora Listener

[English](ARCHITECTURE_EN.md) | [Русский](ARCHITECTURE.md)

Документ содержит подробный инженерный разбор архитектурных решений, алгоритмов, конвейеров обработки данных и технического стека приложения Nora Listener (версия 1.2.1).

## 1. Системная архитектура и выбор платформы

### 1.1. Отказ от Electron в пользу Tauri v2
При проектировании десктопного решения для академической среды ключевыми критериями являлись:
- Минимальное потребление оперативной памяти (приложение должно работать на студенческих ноутбуках с 4–8 ГБ ОЗУ);
- Мгновенный запуск и отсутствие накладных расходов виртуальной машины Chromium на процесс;
- Минимальный размер распространяемого исполняемого файла;
- Нативный доступ к аудиоустройствам операционной системы с низкой задержкой (low-latency audio capture).

В качестве основы был выбран стек **Tauri v2** на базе языка **Rust** и нативного системного веб-движка Windows **WebView2**:
- **Размер дистрибутива**: 21.7 МБ автономный бинарник / 72.8 МБ установщик NSIS с поддержкой Webview2;
- **Потребление ОЗУ в режиме простоя**: 45–65 МБ (в 5–8 раз ниже аналогичных Electron-приложений);
- **Разделение привилегий**: пользовательский интерфейс выполняется в изолированном контексте WebView, а все ресурсоемкие операции (декодирование аудио, цифровая обработка сигналов, запись с микрофона, вызовы API, файловый I/O) выполняются в нативном процессе Rust через типизированные IPC-команды (`invoke`).

## 2. Конвейер захвата и цифровой обработки аудиосигнала (DSP)

### 2.1. Декодирование медиа-контейнеров (`whisper_candle::pcm_decode`)
Для поддержки лекций, записанных на диктофоны, смартфоны или камеры, реализован универсальный декодер на базе библиотеки `symphonia`:
- **Поддерживаемые форматы**: WAV, MP3, AAC, M4A, MP4 (аудиодорожка), FLAC, OGG Vorbis, MKV, CAF.
- **Потоковый процессинг**: файл открывается через `MediaSourceStream`, тип контейнера и кодек определяются эвристическим анализатором (`get_probe()`).
- **Нормализация формата**: аудиопакеты декодируются в линейный буфер `Vec<f32>` с приведением многоканального звука (стерео, 5.1) к монофоническому сигналу путем усреднения отсчетов каналов:
  $$\text{sample}_{\text{mono}} = \frac{1}{C} \sum_{c=1}^{C} \text{sample}_c$$

### 2.2. Низкоуровневый захват с микрофона (`native_audio.rs`)
Захват звука в реальном времени реализован через библиотеку `cpal` с использованием низкоуровневого API Windows **WASAPI**:
- **Многопоточная буферизация**: отсчеты из аудио-колбэка драйвера складываются в потокобезопасный буфер `Arc<Mutex<Vec<f32>>>`.
- **Троттлинг визуализатора**: для предотвращения перегрузки очереди событий IPC частота отправки пиковых значений амплитуды для интерфейсного спектроанализатора ограничена интервалом 40 мс (~25 кадров/сек).
- **Экспорт в WAV без потерь**: при остановке записи буфер упаковывается библиотекой `hound` в стандартный 16-битный PCM WAV с сохранением в защищенную директорию данных приложения (`app_data_dir/recordings/`).

### 2.3. Алгоритмы предварительной очистки и нормализации сигнала (DSP 2.0, `dsp_chain.rs`)
В версии 1.2.0 реализован профессиональный конвейер обработки речевого тракта, решающий проблему тихой речи лектора на большом расстоянии (5–15 м) и записи со встроенных микрофонов ноутбуков:
1. **Полосовой фильтр человеческой речи (Speech Bandpass Filter)**:
   - **Фильтр Баттерворта 2-го порядка ВЧ (High-Pass, 100 Гц)**:
     Устраняет постоянную составляющую (DC offset), вибрации корпуса ноутбука от кулера охлаждения, резонансы стола и сетевой фон 50/60 Гц.
   - **Фильтр Баттерворта 2-го порядка НЧ (Low-Pass, 7500 Гц)**:
     Отсекает высокочастотный шип электроники, высокочастотные гармоники и шум квантования, сужая полосу до информативного спектра человеческой речи.
   - Передаточная функция биквадратного звена:
     $$H(z) = \frac{b_0 + b_1 z^{-1} + b_2 z^{-2}}{1 + a_1 z^{-1} + a_2 z^{-2}}$$
2. **Адаптивный компрессор-лимитер тихой речи (Multi-Stage AGC & Limiter)**:
   - Непрерывное отслеживание огибающей RMS сигнала с быстрой атакой ($40\text{ мс}$) для захвата гласных и плавным спадом ($400\text{ мс}$) для предотвращения «дыхания» фонового шума между словами.
   - **Адаптивный подъем слабого сигнала (Makeup Gain)**: слабослышимый голос лектора издалека усиливается на величину до $+18\text{ дБ}$ (стандарт), $+23.5\text{ дБ}$ (высокий, рекомендован для лекций) или $+28\text{ дБ}$ (ультра) к целевому уровню $0.15\text{ RMS}$.
   - **Soft-Knee компрессор и Brickwall Limiter**: при внезапных громких звуках рядом с микрофоном (кашель, хлопок двери, стук по столу) сигнал мягко компрессируется по плавной кривой выше порога $0.85\text{ FS}$ с жестким потолком $0.98\text{ FS}$, предотвращая клиппинг и хрип.
3. **Динамический детектор речевой активности (Dynamic VAD)**:
   - Вместо жесткого статического порога ($0.012$), отсекавшего тихий голос лектора, используется адаптивное слежение за шумовой полкой помещения с чувствительностью до $0.0025\text{ RMS}$. Это исключает потерю начала и окончания академических предложений.

## 3. Алгоритмы спектральной диаризации спикеров (`diarization.rs`)

Ключевая инженерная особенность Nora Listener — способность разделять речь преподавателя и вопросы студентов полностью локально, без передачи аудио на тяжелые сторонние сервисы диаризации.

### 3.1. Быстрое преобразование Фурье (FFT)
В модуле `diarization.rs` реализовано собственное быстрое преобразование Фурье по алгоритму Кули — Тьюки (Radix-2 Cooley-Tukey) с прореживанием по времени для окон размером $N = 512$ отсчетов:
- **Перестановка с обращением порядка битов (Bit-reversal permutation)**:
  Входной вектор отсчетов переставляется на месте, меняя индекс $i$ на индекс с инвертированными битами.
- **Бабочки Кули — Тьюки**:
  Каскадные вычисления с тригонометрическими поворотными коэффициентами:
  $$W_N^k = e^{-j \frac{2\pi k}{N}} = \cos\left(\frac{2\pi k}{N}\right) - j \sin\left(\frac{2\pi k}{N}\right)$$
- **Оконное взвешивание Ханна (Hann Window)**:
  Перед вычислением спектра каждый 512-точечный фрейм умножается на окно Ханна для устранения спектральных утечек (spectral leakage):
  $$w[n] = 0.5 \left(1 - \cos\left(\frac{2\pi n}{N - 1}\right)\right)$$

### 3.2. Спектральный центроид (Spectral Centroid)
Для оценки тембрального профиля (яркости голоса) вычисляется спектральный центроид фрейма:
$$\text{Centroid} = \frac{\sum_{k=1}^{N/2} f_k \cdot |X[k]|^2}{\sum_{k=1}^{N/2} |X[k]|^2}$$
где $f_k = k \cdot \frac{F_s}{N}$ — физическая частота $k$-го бина, а $|X[k]|^2$ — спектральная мощность.

### 3.3. Детектирование основного тона (F0 Pitch Detection)
Определение высоты голоса основано на нормализованной автокорреляционной функции (Normalized Autocorrelation):
$$R(\tau) = \frac{\sum_{n=0}^{W-1} x[n] \cdot x[n + \tau]}{\sqrt{\sum_{n=0}^{W-1} x^2[n] \cdot \sum_{n=0}^{W-1} x^2[n + \tau]}}$$
- **Диапазон поиска задержки (lag)**: ограничен физиологическими пределами человеческого голоса от 75 Гц до 360 Гц:
  $$\tau_{\min} = \left\lfloor \frac{F_s}{360} \right\rfloor, \quad \tau_{\max} = \left\lceil \frac{F_s}{75} \right\rceil$$
- **Критерий вокализации**: если пиковая корреляция $\max_{\tau} R(\tau) > 0.42$, участок классифицируется как звонкая речь (гласные звуки с выраженной периодичностью), а частота тона вычисляется как:
  $$F_0 = \frac{F_s}{\tau_{\text{best}}}$$

### 3.4. Кластеризация и сопоставление спикеров
1. **Формирование акустических кластеров**:
   Сегменты речи группируются на основе евклидова расстояния в двумерном пространстве признаков $(F_0, \text{Centroid})$. В лекционном сценарии доминирующий непрерывный кластер автоматически маркируется как «Преподаватель» (Speaker 1), а фрагменты с отличной высотой тона и формантами — как «Студент / Аудитория» (Speaker 2).
2. **Временное сопоставление (Time-Alignment)**:
   При получении распознанных текстовых чанков от Whisper структура `DiarizationResult` сопоставляет временные границы фразы $[t_{\text{start}}, t_{\text{end}}]$ с акустическими сегментами методом `get_speaker_at(time_sec)` с допуском $\pm 150$ мс, расставляя маркеры спикеров без разрыва смысловых предложений.

## 4. Конвейер нейросетевого распознавания (`cloud_api.rs`)

### 4.1. Сверхбыстрая облачная обработка (Groq Cloud LPU)
Для обеспечения скорости, превосходящей реальное время более чем в 200 раз, задействован специализированный тензорный процессор Groq LPU (Language Processing Unit):
- **Модели**:
  - `whisper-large-v3` (1.55 млрд параметров) — максимальное качество распознавания специализированной научной терминологии.
  - `whisper-large-v3-turbo` — оптимизированная архитектура для молниеносной обработки.
- **In-Memory потоковое чанкирование**:
  Входной PCM-массив разбивается на 10-минутные блоки. Каждый блок кодируется в формат WAV непосредственно в оперативной памяти с использованием `std::io::Cursor<Vec<u8>>` и `hound::WavWriter`. Это исключает износ диска и временные I/O-блокировки.
- **Контекстный промптинг**:
  К каждому запросу добавляется системная затравка:
  > *"Академическая лекция в университете. Преподаватель объясняет материал студентам. Высшая математика, дискретная математика, алгоритмы, программирование, формулы, термины..."*
  Это ориентирует языковую декодирующую голову Whisper на корректную расстановку знаков препинания, заглавных букв и академических терминов.

### 4.2. Эвристический фильтр галлюцинаций Whisper (`is_hallucination`)
Модели семейства Whisper при длительных паузах или фоновом шуме склонны генерировать зацикленные артефакты обучающей выборки YouTube (например: «Субтитры создавал...», «Спасибо за просмотр», «Продолжение следует»).
В функции `is_hallucination` реализован нормализующий лексический сканер, который очищает строку от спецсимволов и отсекает известные шаблоны галлюцинаций до их попадания в историю и интерфейс.

### 4.3. Автономный локальный движок (`whisper_candle.rs`)
В качестве резервного оффлайн-режима реализована прямая интеграция фреймворка **Candle** (HuggingFace) на чистом Rust:
- Загрузка весов моделей GGML/SafeTensors напрямую в системную память;
- Вычисление 80- или 128-канальной мел-спектрограммы с использованием встроенных весов мел-фильтров (`melfilters.bytes`);
- Полноценный прямой проход через Transformer Encoder и авторегрессионный декодер;
- Поддержка многоязычной токенизации (`multilingual.rs`) без внешних Python-окружений.

## 5. Интеллектуальный синтез академического конспекта

### 5.1. Модель и семантический промптинг
Конспектирование вызывается кнопкой **«Сделать умный конспект»** и выполняется моделью `llama-3.3-70b-versatile` на LPU Groq:
- **Структурирование**: сырой стенографический текст трансформируется в структурированный конспект:
  - Основная тема лекции;
  - Ключевые термины и их академические определения;
  - Пошаговые тезисы и логика доказательств;
  - Списки важных выводов и экзаменационных вопросов.
- **Режим «Показывать цитаты преподавателя»**: при активации чекбокса модель извлекает буквальные цитаты ключевых формулировок лектора с контекстным комментарием.

### 5.2. Санитайзинг и интеграция формул KaTeX (`test_sanitize_summary`)
При генерации математических выражений LLM часто допускает ошибки экранирования или разметки. Модуль `sanitize_summary` производит постобработку:
1. Конвертация несимметричных или поврежденных тегов `\[ ... \]`, `\( ... \)` в стандартный Markdown-синтаксис `$$...$$` (блочные формулы) и `$...$` (инлайн формулы).
2. Балансировка открывающих и закрывающих символов `$`, чтобы предотвратить сбой синтаксического анализатора KaTeX на клиенте.
3. Экранирование спецсимволов валюты и Markdown-разметки вне математических блоков.

### 5.3. Контекстный синтез учебных материалов (Context Ingestion Engine)
Начиная с версии 1.0.1, в Nora Listener реализован многоуровневый конвейер контекстной верификации лекций (`ContextPanel.tsx` + `contextExtractor.ts`):
1. **Локальный разбор OpenXML и PDF**:
   - Презентации (`.pptx`) и документы (`.docx`) парсятся непосредственно в браузере с помощью библиотеки `jszip` без использования сторонних серверов и без необходимости установки Microsoft Office.
   - Из презентаций по маске `ppt/slides/slide*.xml` извлекаются текстовые узлы `<a:t>`, сгруппированные по номерам слайдов (`--- Слайд N ---`).
   - Из документов Word по структуре `word/document.xml` извлекаются параграфы `<w:p>` и текстовые фрагменты `<w:t>` с разэкранированием сущностей XML.
   - Из файлов PDF потоково декодируются контентные блоки текстовых потоков.
2. **Семантическая классификация**:
   Материалы автоматически категоризируются на слайды презентации (`presentation`), студенческие заметки (`notes`), учебную литературу (`literature`) и вспомогательные файлы (`other`).
3. **Двухпоточный синтез (Dual-Source Academic Synthesis)**:
   При формировании конспекта функция `formatContextForPrompt` упаковывает извлеченные данные в системный блок. В системный промпт Норы внедряются строгие академические правила:
   - **Хронологический приоритет**: аудиозапись лекции является основой структуры конспекта.
   - **Верификация терминов и формул**: искаженные устной речью термины и фамилии ученых сверяются со слайдами и литературой.
   - **Восстановление визуальных пропусков**: формулы, опущенные лектором на словах (*«как видно из формулы на экране»*), извлекаются из слайда и включаются в конспект в синтаксисе LaTeX с пометкой `[Из материалов лекции / слайдов]`.

### 5.4. Динамический системный промптинг и редактор Норы
В настройках приложения (`SettingsModal.tsx`) реализован редактор системного промпта Норы:
- Пользователь может адаптировать базовые системные правила конспектирования под специфику своего факультета (например, требовать больше кода для IT-специальностей или больше формул для теоретической физики).
- Кастомный промпт хранится в хранилище Zustand (`appStore.ts`) с автосохранением в `localStorage` и возможностью мгновенного отката к эталонному академическому промпту (`resetPromptToDefault`).


### 5.6. Потоковая транскрибация речи в реальном времени (Real-Time Live Transcription Engine)
В версии 1.1.0 реализован конвейер потокового распознавания речи на лету во время записи с микрофона:
1. **Неблокирующий WASAPI захват (`native_audio.rs`)**:
   - Высокоприоритетный системный поток `cpal` передает сэмплы f32 параллельно в два независимых русла:
     - Основной буфер (`Arc<Mutex<Vec<f32>>>`) для сохранения итогового полного несжатого WAV-файла 16 кГц 16-бит на диск в каталог `app_data_dir/recordings/`.
     - Неблокирующий канал `std::sync::mpsc::channel` в отдельный фоновый поток рабочего воркера `nora-realtime-worker`.
2. **4-уровневая система сохранения непрерывного контекста фраз (Context Preservation)**:
   - **Уровень 1 (Адаптивный VAD-срез)**: расчет среднеквадратичной мощности RMS на 50-мс кадрах. Срез аудио инициируется исключительно в паузах тишины лектора (`vad_silence_ms`: 400–1200 мс) либо по достижению верхнего окна (`chunk_window_sec`: 4–12 сек) в локальном минимуме громкости.
   - **Уровень 2 (Акустический нахлест ~500 мс)**: начало каждого нового чанка захватывает 500 мс хвоста предыдущего чанка, предотвращая отсечение начальных фонем и звуков речи.
   - **Уровень 3 (Кондиционирование декодера Whisper через prompt)**: в запрос к Groq Whisper передается `previous_tail` (последние 25 слов предыдущего текста). Модель продолжает мысль с сохранением грамматического строя, падежей и пунктуации.
   - **Уровень 4 (Текстовый дедупликатор на стыке `stitch_transcription_tail`)**: нативный алгоритм в Rust находит максимальный префиксно-суффиксный нахлест слов между смежными чанками, схлопывает дубликаты и выравнивает регистр первой буквы.
3. **Реактивное отображение в интерфейсе**:
   - События `realtime-transcription-chunk` доставляют распознанные блоки в React-компонент `App.tsx`.
   - Текст плавно заполняет редактор с автоскроллом к последним строкам.
   - Сразу после нажатия кнопки «Остановить запись» лекция уже полностью расшифрована и готова к немедленному формированию умного конспекта («Сделать умный конспект»).

### 5.5. Пользовательский направляющий контекст (Clarifying Prompt Engine)
В версии 1.0.2 внедрен механизм персональных указаний пользователя к формируемому конспекту (`ClarifyingPromptPanel.tsx`):
1. **Эргономика и размещение**:
   - Поле ввода расположено непосредственно под панелью контекста занятия и над панелью рабочих вкладок.
   - Оснащено индикацией заполнения (бейдж с динамическим подсчетом символов), подсказками-примерами и кнопкой мгновенной очистки.
2. **Сессионная изоляция и привязка к лекции**:
   - Уточняющий контекст строго изолирован в рамках текущей сессии: текст привязан к объекту транскрипции в `historyStore` (поле `clarifyingPrompt`).
   - При переключении между лекциями в дереве папок сохраняются и восстанавливаются персональные пожелания для каждой конкретной записи.
   - При нажатии «Новая сессия» поле очищается вместе с остальными параметрами активной сессии.
3. **Сквозная доставка и инъекция в системный промпт**:
   - Текст пожеланий передается через типизированную цепочку вызовов: `App.tsx` -> `summarizer.ts` -> нативная команда Tauri `generate_summary` (`lib.rs`) -> `cloud_api::summarize_text`.
   - В итоговый запрос к модели LLM (Groq) внедряется приоритетный блок директив:
     ```text
     ОСОБЫЕ ПОЖЕЛАНИЯ И УТОЧНЯЮЩИЕ УКАЗАНИЯ ПОЛЬЗОВАТЕЛЯ К ЭТОМУ КОНСПЕКТУ:
     [текст указаний пользователя]
     Обязательно учти эти пожелания при раскрытии тем, расстановке акцентов и глубине изложения материала.
     ```
   - Модель обязана расставить акценты в соответствии с запросом студента (углубить доказательства, сфокусироваться на подготовке к экзамену, привести практический программный код и т.д.), не нарушая базовую 5-секционную академическую структуру конспекта.

### 5.7. Система отслеживания релизов и обновлений (Update Checker)

Для непрерывной поддержки пользователей в приложении реализован конвейер мониторинга обновлений:
1. **Нативный модуль проверки (`src-tauri/src/update_checker.rs`)**:
   - Выполняет легковесный асинхронный HTTPS-запрос к публичному эндпоинту GitHub Releases API (`https://api.github.com/repos/unnamed-Light/nora-listener/releases/latest`) с заголовком `User-Agent: Nora-Listener-Desktop`.
   - Запрос не требует авторизации и токенов, не зависит от CORS веб-оболочки и учитывает системные прокси-настройки.
2. **Алгоритм сопоставления версий (SemVer Parser)**:
   - Парсит строки версий (с префиксами `v`/`V` и суффиксами hotfix) в структуру `SemVer { major, minor, patch }`.
   - Сравнивает текущую сборку (`env!("CARGO_PKG_VERSION")`) с последним опубликованным тегом GitHub.
3. **Фоновая и ручная проверка**:
   - *Тихая фоновая проверка*: запускается через 3.5 секунды после старта интерфейса без блокировки основного потока.
   - *Ручная проверка*: доступна в окне «Настройки» с выводом статуса проверки в реальном времени.
4. **Интерактивное окно обновления (`UpdateModal.tsx`)**:
   - При обнаружении нового релиза выводит модальное окно Fluent UI с перечнем изменений (Release Notes), датой релиза и версиями.
   - По кнопке «Обновиться» инициирует безопасное открытие страницы релиза в системном браузере через `tauri-plugin-shell`.
   - Поддерживает пропуск конкретной версии (`ignoredUpdateVersion`) и отключение автопроверки в настройках.

## 6. Архитектура интерфейса и клиентская оптимизация (React 19 + TypeScript)

### 6.1. Дерево папок и жестовый Drag-and-Drop (`FolderTree.tsx`)
В версии 1.0.1 организация лекций оптимизирована для максимального удобства:
- **Полнострочный захват**: удалены устаревшие иконки-хэндлы со стрелками. Захват карточки лекции или папки осуществляется по всей площади строки с нативным стилем курсора `cursor: grab`.
- **Бесконфликтный Pointer Events движок**: использование событий `onPointerDown`, `onPointerMove`, `onPointerUp` в сочетании с `document.elementFromPoint` гарантирует плавное перемещение без паразитных эффектов выделения текста и конфликтов с OLE-буфером Windows.
- **Интеллектуальное автораскрытие**: при наведении на закрытую папку дольше 450 мс папка раскрывается автоматически.

### 6.2. Производительный рендеринг текста (`FastTextarea.tsx`)
Полуторачасовая лекция содержит от 10 000 до 25 000 слов (до 150 КБ чистого текста). Стандартные контроли React при таком объеме вызывают ощутимые микрофризы при вводе символов.
- В компоненте `FastTextarea` применено разделение локального состояния: контролируемый ввод изолирован во внутреннем буфере DOM через `useRef`, а синхронизация с глобальным состоянием Zustand происходит по событию `onBlur` или с дебаунсом 300 мс.

### 6.3. Парсер и рендерер KaTeX (`mathRenderer.ts`)
Рендеринг математических конспектов выполняется по двухфазной схеме:
1. Регулярное выражение выделяет блочные выражения `(?:$$)([\s\S]*?)(?:$$)` и инлайн формулы `(?:$)(.*?)(?:$)`.
2. Математические фрагменты передаются компилятору `katex.renderToString` с флагом `throwOnError: false`.
3. Окружающий текст форматируется парсером `marked` с санитизацией DOMPurify для защиты от XSS-уязвимостей.
4. В случае синтаксической ошибки в формуле вместо аварийного падения отображается исходный LaTeX-код с подсветкой синтаксиса.

### 6.4. Адаптивный сплит-интерфейс и селективный экспорт (`App.tsx`)
1. **Эргономика элементов управления**:
   - Переключатель точности («Повышенная точность» / «Повышенная скорость») вынесен в блок управления непосредственно рядом с кнопкой «Расшифровать», обеспечивая мгновенный доступ к выбору модели на любом экране.
   - В режиме двух окон кнопки «Предпросмотр» и «Редактор» вынесены исключительно в заголовок подокна конспекта, устраняя дублирование в глобальной панели.
2. **Селективный экспорт в сплит-режиме**:
   Кнопки экспорта («Word», «PDF», «Сохранить .md») в сплит-окне оснащены выпадающим меню на базе Fluent UI (`Menu`, `MenuTrigger`, `MenuPopover`, `openOnHover`), позволяя сохранять:
   - *Только конспект*;
   - *Только транскрипт*;
   - *Объединенный файл (Конспект + Транскрипт)*.
3. **Адаптивная модальная геометрия**:
   В модальных окнах (`SettingsModal.tsx`) внедрена строгая flex-структура с `minHeight: 0`, `flexGrow: 1` и `overflowY: auto`. Это гарантирует комфортный вертикальный скроллинг длинных списков параметров на любых разрешениях мониторов и жесткую фиксацию футера с кнопкой «Готово».

### 6.4. Адаптивная геометрия рабочей области и вертикальный скроллинг главного окна (v1.2.1)
В версии 1.2.1 полностью переработана геометрическая модель центральной рабочей области:
- **Проблема сжатия редактора при обилии панелей**: При одновременном открытии карточек аудио (дропзона, выбор микрофона, индикатор записи), кнопок выбора режима, контекстной панели (`ContextPanel`), поля уточняющего промпта (`ClarifyingPromptPanel`), тулбара поиска и панели обнаруженных спикеров суммарная высота элементов управления достигает ~450–550 px. Ранее из-за жесткой привязки к высоте родительского контейнера flexbox сжимал текстовый блок (`textareaContainer`) до щели в 50–100 px без активации полосы прокрутки.
- **Гарантированная минимальная высота (`clamp(420px, 52vh, 850px)`)**: Для `textareaContainer` зафиксировано правило `minHeight: clamp(420px, 52vh, 850px)` и `flexShrink: 0`, а для вложенных компонентов (`textareaWrapper`, `markdownPreview`, `splitContainer`, `splitPane`) — минимальные высоты от 380 до 440 px. Это гарантирует, что поле для чтения и редактирования никогда не сомнется до нечитаемого состояния.
- **Полноценный вертикальный скроллинг (`overflowY: 'auto'`)**: Контейнер `mainContent` получил неограниченную прокрутку по оси Y с кастомной плавной стилизацией скроллбаров Fluent UI (`tokens.colorNeutralStroke2`). Когда суммарная высота открытых панелей и текстового редактора превышает высоту экрана, плавно скроллится вся страница.
- **Фиксация панели действий (`sticky tabRow`)**: Блок переключения вкладок («Полный транскрипт», «Умный конспект», «Два окна») и кнопок действий («Сделать умный конспект», «Экспорт») переведен в режим `position: sticky; top: 0; zIndex: 10` с непрозрачным фоном. При прокрутке панелей управления вниз кнопки генерации конспекта и экспорта остаются зафиксированными вверху экрана для мгновенного доступа.

## 7. Модель хранения данных и экспорт

### 7.1. Реляционная иерархия Zustand (`historyStore.ts`)
История сессий организована по реляционному принципу и сохраняется в `localStorage` через middleware `persist`:
```typescript
interface Folder {
  id: string;
  name: string;
  parentId: string | null;
}

interface Transcription {
  id: string;
  title: string;
  date: string;
  createdAt: string;       // ISO 8601 метка для хронологической сортировки
  text: string;           // Полный стенографический транскрипт с разметкой
  summary?: string;       // Умный конспект с KaTeX
  folderId: string | null;// Ссылка на родительскую папку (null = корень)
}
```
- **Сортировка лекций**: реализована чистая функция `sortLectures`, поддерживающая 4 режима: по дате создания (новые/старые) и по алфавиту заголовков (А–Я / Я–А) с учетом языковых локалей (`localeCompare`).

### 7.2. Клиентский генератор документов (`exporter.ts`)
Экспорт файлов выполняется на 100% на стороне клиента без привлечения внешних серверов:
- **DOCX**: библиотека `docx` программно строит дерево документа (абзацы, заголовки, списки, выделения полужирным) и генерирует бинарный `Blob`.
- **PDF**: для конспектов с формулами KaTeX используется связка `html2canvas` + `jspdf`. Визуализированный DOM-контейнер с векторными формулами растеризуется с субпиксельным качеством и разбивается на страницы формата A4 с учетом полей.
- **Поддержка областей экспорта**: функции экспорта принимают параметр `scope?: 'summary' | 'transcript' | 'both'`, генерируя релевантные заголовки, суффиксы файлов и форматирование для раздельных или составных документов.
- **Сохранение на диск**: путь к целевому файлу запрашивается через системный диалог `@tauri-apps/plugin-dialog`, после чего байты записываются нативным Rust-вызовом `write_binary_file`.

### 7.3. Подсистема автоматического отслеживания обновлений (`update_checker.rs`, `UpdateModal.tsx`)
Начиная с версии 1.2.0 приложение включает встроенную систему проверки версий с GitHub Releases:
- **Двухуровневая архитектура проверки**:
  - Нативный фоновый поток на Rust (`check_github_release`) использует `reqwest` с TLS для прямого запроса к GitHub API (`/repos/unnamed-Light/nora-listener/releases/latest`).
  - Резервный фронтенд-фоллбек через стандартный браузерный `fetch` на случай ограничений среды.
- **Алгоритм семантического версионирования (SemVer)**:
  - Строгий парсер версий с поддержкой префиксов `v`, суффиксов хотфиксов и цифровых мажоров, миноров и патчей (`is_newer_version`).
- **Пользовательский интерфейс и нотификации**:
  - Фоновая ненавязчивая проверка через 3.5 секунды после старта приложения.
  - Информативное диалоговое окно (`UpdateModal.tsx`) с описанием изменений (Release Notes), кнопкой перехода к релизу на GitHub для скачивания и возможностью пропустить конкретную версию.
  - Ручная проверка обновлений в окне «Настройки» с визуальным бейджем текущего статуса.

## 8. Итоги и инженерные выводы

Архитектура **Nora Listener v1.2.1** демонстрирует эффективный баланс между локальными вычислениями и облачным ускорением:
1. **Безопасность и автономность**: конфиденциальная обработка звука (DSP 2.0, полосовая фильтрация, диаризация, нарезка) и разбор учебных документов (.docx, .pptx, .pdf) выполняются строго локально на машине пользователя.
2. **Максимальная производительность**: использование Groq Cloud LPU решает проблему медленной генерации на слабых пользовательских GPU, обеспечивая расшифровку и синтез за считанные секунды.
3. **Эргономика и надежность**: продуманная система хранения, полосовой фильтр и компрессор тихой речи, полнострочный Drag-and-Drop, сплит-экран, селективный экспорт и динамический промптинг делают продукт полноценным рабочим инструментом для академической деятельности.
